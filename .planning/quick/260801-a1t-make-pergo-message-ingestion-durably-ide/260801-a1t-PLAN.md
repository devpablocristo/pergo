# Quick Plan: durable message idempotency for Pymes

## Objective

Close the real PerGo/Pymes reliability gap with a durable ingestion receipt and
tenant-safe, non-secret routing while preserving PerGo ownership of provider
credentials.

<task>
<files>
- internal/platform/postgres/migrations/031_message_idempotency.sql

- internal/repository/message_idempotency_test.go
- internal/api/handler/message.go
- internal/api/handler/message_test.go
- cmd/pergo/main.go
</files>
<action>
- Persist an atomic workspace-scoped claim containing key, canonical request
  hash, stable message receipt, trace and acceptance state.
- Require and validate Idempotency-Key for callers using durable semantics.
- Return the original 202 receipt for identical accepted replays; reject a
  different hash with stable `idempotency_key_reused` HTTP 409.
- Let pending identical retries safely resume ingestion with the stored trace,
  then atomically mark the receipt accepted.
- Extend the JetStream duplicate window beyond the complete HTTP retry horizon
  to protect the publish/acceptance crash window.
</action>
