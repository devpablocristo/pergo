# Automatizar despliegue seguro de PerGo en GCP compartido

## Objetivo

Agregar automatización local, determinística y fail-closed para planificar,
auditar y aplicar la topología PerGo de Pymes en
`pymes-dev-352318/us-central1`, sin provisionar NATS ni ejecutar cambios cloud
durante esta tarea.

## Must haves

- STG y PRD tienen nombres, identidades, bases, usuarios y secretos separados.
- La imagen se acepta sólo como referencia inmutable `@sha256`.
- API privada: sólo `pymes-v3-worker-{env}` puede invocarla.
- Webhook público: el perfil de runtime sólo sirve callbacks y probes.
- Worker usa Cloud Run Worker Pool y `migrate` usa Cloud Run Job.
- Cada perfil monta una credencial NATS `.creds` distinta; NATS es externo.
- PostgreSQL usa Cloud SQL connector y Direct VPC usa la red/subred existentes.
- Secret Manager entrega únicamente versiones numéricas explícitas.
- `plan` no muta; `audit` sólo lee; `apply` requiere confirmación exacta y
  aborta antes de mutar ante cualquier preflight incompleto.
- Pruebas shell demuestran las garantías anteriores sin acceder a GCP.

## Tareas

1. Crear biblioteca común y entrypoints `plan`, `audit` y `apply`, con
   validación de inputs, prerequisitos, IAM mínimo y orden de rollout.
2. Crear fixtures/fake de `gcloud` y pruebas shell determinísticas para caminos
   felices y fallos críticos.
3. Documentar el runbook, preparación humana de Cloud SQL/Secret Manager/NATS,
   validación y rollback; enlazarlo desde la guía de despliegue.

## Verificación

- `bash scripts/deploy/pergo-gcp-test.sh`
- `bash -n scripts/deploy/pergo-gcp-*.sh`
- `go test ./cmd/pergo -run 'TestRuntimeProfile(RouteIsolation|ProcessRoles)'`
- `git diff --check`

## Restricciones de ejecución

- No ejecutar `apply`.
- No crear/modificar recursos GCP.
- No generar ni subir credenciales reales.
- No commitear ni pushear desde esta tarea delegada.
