# Plan: Durable Pymes v3 delivery contract

## Objective

Make PerGo's real `POST /api/v1/messages` behavior match the private contract
consumed by Pymes: workspace-scoped idempotency, a stable receipt, and signed
delivery events whose `message_id` is that same receipt.

## Tasks

1. Add a PostgreSQL ingress ledger keyed by workspace and idempotency key, with
   payload hash, stable receipt, trace binding, expiring claim and queued state.
2. Require and validate `Idempotency-Key` and `X-Trace-ID` when the durable
   ledger is wired; replay identical requests, reject changed payloads, and
   prevent concurrent publication.
3. Use one deterministic receipt identity across ingress, dispatch, and
   `sent`/`delivered`/`read`/`failed` webhook events.
4. Publish provider delivery/read receipts to `webhooks.events` while retaining
   the existing internal `messages.status_updated` event.
5. Wire the repository in the production composition root and add unit,
   PostgreSQL, concurrency, replay, and delivery-event contract tests.
6. Run formatting, focused tests, race tests where practical, and the existing
   full Go suite without publishing or pushing.
